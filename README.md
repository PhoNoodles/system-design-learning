# System Design Learning

A guided system-design course based on [The System Design Primer](https://github.com/donnemartin/system-design-primer), with GitHub issues as the durable learning record.

## Start or continue

**Start with [SD-01.01 — Performance vs scalability](https://github.com/PhoNoodles/system-design-learning/issues/1).** At the 2026-11-24 setup audit, no learning assessments had occurred. Future sessions must read the live issue history before choosing the next lesson.

To resume in a later conversation:

> Continue my system design learning from PhoNoodles/system-design-learning. Read the learning protocol and latest issue session records before choosing the next step.

The assistant follows your selected topic or the last learning session's recorded next step. Otherwise, it starts the earliest ready unfinished lesson. It uses prior demonstrated evidence to avoid unnecessary repetition and asks one question at a time.

## How progress is recorded

The canonical issue's state and dated comments are authoritative. An open lesson can be unstarted, in progress, blocked or awaiting assessment; its latest learning-session comment explains the status. A completed lesson needs independent evidence for **every essential objective** and at least **8/10** across conceptual accuracy (4), mechanism (2), tradeoffs (2) and application (2).

Each session records what you were asked, what you demonstrated, any hints, the assessment or “not assessed,” remaining gaps and one concrete next action. Reading a topic, creating an issue, or seeing it in an earlier chat does not by itself establish mastery. Administrative duplicates #19 and #20 remain closed and excluded. No separate progress spreadsheet or static completion counter needs synchronization.

## Orientation and review

The Primer's [study guide](https://github.com/donnemartin/system-design-primer#study-guide) and [starting overview](https://github.com/donnemartin/system-design-primer#system-design-topics-start-here) provide a broad map. Its [scalability lecture](https://github.com/donnemartin/system-design-primer#step-1-review-the-scalability-video-lecture) and [scalability article](https://github.com/donnemartin/system-design-primer#step-2-review-the-scalability-article) are optional orientation resources; use diagnostics to decide which foundations need attention.

The [three Anki decks](https://github.com/donnemartin/system-design-primer#anki-flashcards) cover system-design concepts, system-design exercises and object-oriented exercises. Use them for deliberate retrieval practice, then demonstrate understanding in an issue assessment. Record the specific review and any gaps; a flashcard streak is not a lesson-completion record.

The main path includes practical extensions relevant to software engineering and SAP/ABAP integrations. They are labeled in the index and issue bodies. Optional object-oriented exercises, additional system-design prompts and selected architecture readings are available when they match your goals.

## Source quality and attribution

The Primer is the foundation and a reference collection. Detailed supplemental lessons use current primary documentation or original papers, selected and recorded when taught. Historical latency values, product features and sample architectures need context; check current behavior before making implementation decisions. A source mapping establishes curriculum coverage, not correctness of every external page or proof of learning.
