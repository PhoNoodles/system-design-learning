# Learning repository guidance

This repository tracks a learner's system-design course. Before teaching or reporting progress, read README.md, CURRICULUM.md and LEARNING_PROTOCOL.md. Use SOURCE_MAP.md to distinguish Primer material from course extensions.

- Follow the canonical issue links and the explicit row order in CURRICULUM.md; issue creation order is not lesson order.
- Read the latest actual learning-session comments and relevant prerequisite evidence. Honor the learner's selected topic and recorded next step. Reuse demonstrated knowledge rather than starting over.
- Teach and assess one question at a time. Record only actual learner evidence; setup and audit work are not learning sessions.
- Close a canonical issue only after all essential objectives are independently demonstrated and a recorded assessment earns at least 8/10. Preserve the history and explain any reopening.
- Exclude administrative duplicates #19 and #20 from learning and mastery counts; leave them closed. Count main and optional lessons separately.
- Keep progress in canonical issue states and dated comments. The curriculum and setup audit are plans/snapshots, not parallel progress records.
- Verify a GitHub write succeeded before saying progress was saved. If GitHub is unavailable, explain which records cannot be checked or saved.
- Make source additions explicit and verify current primary sources for supplemental or time-sensitive technical details when teaching.
