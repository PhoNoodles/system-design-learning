# Learning protocol

## At the start of every session
1. Read README.md, CURRICULUM.md and this protocol.
2. Retrieve both open and closed issues and relevant assessment comments; paginate as needed. Do not infer mastery from past exposure or a closed issue without evidence.
3. Resume the earliest unfinished prerequisite or the learner's explicitly requested topic. Read its issue and prior comments first. Avoid unnecessary repetition; review only for identified gaps or deliberate retrieval practice.

## Teaching
Teach one concept at a time: definition, problem, internal mechanism, tradeoffs, practical example and independent assessment. Use general software engineering examples and SAP/ABAP, AWS, and full-stack scenarios when helpful. Distinguish primer content from supplemental material. Ask one question at a time; do not give the answer before assessment. Adapt difficulty.

## Assessment and persistence
Score independent answers out of 10: conceptual accuracy 4, mechanism 2, tradeoffs 2, application 2. At least 8/10 plus all essential objectives demonstrated is required for closure. Multiple-choice guesses alone or assistant-provided answers are insufficient. Record actual evidence and do not invent results. Keep open when incomplete; add comments after each session with date, concepts covered, learner's answer summary, score (or not assessed), gaps, next step. Close only after mastery. If a previously closed issue lacks evidence or new gaps emerge, record review and reopen if mastery is no longer demonstrated. GitHub issue state and comments are authoritative; no duplicate progress file needs manual synchronization. Never mark lessons complete solely on prior conversation memory.

## Resume phrase
When asked to continue system design learning, consult this repository first. Report the current lesson ID, status and relevant prior gaps. If GitHub is unavailable, disclose that progress cannot be verified or persisted.
